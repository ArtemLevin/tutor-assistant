# Итоговые форматы аудиозаписи

## Контракт

Tutor Assistant всегда записывает realtime-чанки в WAV PCM16. После завершения занятия приложение:

1. объединяет чанки микрофона и системного звука;
2. создаёт внутренний WAV-мастер `lesson.wav`;
3. проверяет качество дорожек;
4. формирует выбранный пользовательский файл ровно один раз из WAV-мастера;
5. проверяет кодек, длительность, sample rate и количество каналов через FFprobe;
6. атомарно заменяет итоговый файл после успешной проверки.

WAV-мастер сохраняется при любых сбоях кодирования. Это позволяет повторить конвертацию без новой записи занятия. Низкоуровневый `recording.recorder` отвечает только за WAV; создание M4A/MP3 выполняется слоем `recording.output`.

## Доступные форматы

| Формат | Кодек | Параметры | Назначение |
|---|---|---:|---|
| M4A | AAC | target 96 кбит/с | Значение по умолчанию; компактный архив уроков |
| MP3 | MP3 | target 128 кбит/с | Максимальная совместимость с проигрывателями |
| WAV | PCM16 | без сжатия | Монтаж, диагностика и lossless-хранение |

Параметр bitrate для M4A/MP3 задаёт цель кодировщику. Средний bitrate, который FFprobe сообщает для готового файла, зависит от содержимого и не используется как критерий целостности. В частности, тишина и низкосложный сигнал могут давать существенно меньшее среднее значение.

M4A и MP3 требуют `ffmpeg` и `ffprobe` в `PATH`. WAV поддерживает встроенный потоковый mixer при отсутствии FFmpeg.

## GUI

Переключатель расположен в подробном режиме:

`Занятие → Параметры занятия → Итоговый формат аудио`

Выбор сохраняется в `config/app.yaml`:

```yaml
recording:
  output_format: m4a
```

Быстрый запуск использует последнее сохранённое значение. Переключатель блокируется на время активной записи.

## Session manifest

Новые сессии после исправления аудиофинализации используют schema version 6 и сохраняют:

- `output_format`;
- `output_codec`;
- `output_encoder`;
- `output_bitrate_kbps` — заданный target;
- `actual_output_bitrate_bps` — диагностическое значение FFprobe, если оно доступно;
- `output_duration_seconds`;
- `output_sample_rate_hz`;
- `output_channels`;
- `master_file`;
- `output_file`;
- `encoding_completed_at`.

Сессии прежних версий без `output_format` восстанавливаются в WAV. Это сохраняет совместимость существующего архива.

## Сценарии отказа

### FFmpeg или FFprobe отсутствует

Запуск M4A/MP3 блокируется до начала занятия с понятным сообщением об установке полного комплекта FFmpeg.

### Кодирование завершилось ошибкой

`session.json` получает статус `encoding_failed`, текст ошибки и путь к WAV-мастеру. WAV-мастер остаётся пригодным для транскрибации и повторного восстановления. Сессии со статусом `encoding_failed` входят в автоматический поиск восстанавливаемых записей.

### Повреждённый итоговый файл

FFprobe обязан подтвердить ожидаемый кодек, наличие аудиопотока, положительную и близкую к WAV-мастеру длительность, совпадающие sample rate и количество каналов. До успешной проверки временный файл не становится итоговым.

### Попытка повторного lossy-кодирования

Финализация M4A/MP3 принимает только WAV-мастер. Если в неё ошибочно передан уже закодированный файл, операция завершается контролируемой ошибкой вместо M4A→M4A или MP3→MP3 транскодирования.

## Ручная проверка

1. Убедиться, что `ffmpeg -version` и `ffprobe -version` выполняются из PowerShell.
2. Выбрать M4A, записать короткое занятие с речью и проверить `lesson.m4a` вместе с `lesson.wav`.
3. Повторить M4A с длинными паузами/тишиной и убедиться, что низкий средний bitrate не блокирует финализацию.
4. Повторить проверку для MP3 и WAV.
5. Открыть `session.json` и сверить формат, кодек, target bitrate, диагностический actual bitrate и имена файлов.
6. Временно убрать FFmpeg из `PATH` и проверить блокировку M4A/MP3 до старта.
7. Создать/оставить сессию в `encoding_failed`, перезапустить приложение и убедиться, что recovery предлагается и пересоздаёт выбранный delivery-файл из `lesson.wav`.
8. Запустить recovery старой session version 3 и убедиться, что результатом становится WAV.
