# GigaAM как локальный транскрибатор

Tutor Assistant поддерживает два локальных движка распознавания речи:

- `faster_whisper` — вариант по умолчанию и полностью совместимое прежнее поведение;
- `gigaam` — GigaAM v3 от Salute Developers.

В рабочем интерфейсе движок выбирается в поле **«Транскрибатор»** на форме занятия. Выбор сохраняется в `config/app.yaml` и используется для следующих заданий транскрибации.

## Рекомендуемая модель

По умолчанию используется `v3_e2e_rnnt`. E2E-вариант выбран потому, что помимо распознавания речи выполняет пунктуацию и нормализацию текста, что лучше соответствует длинным русскоязычным учебным занятиям.

Конфигурация:

```yaml
whisper:
  provider: gigaam
  gigaam_model: v3_e2e_rnnt
  gigaam_device: auto
  gigaam_chunk_seconds: 20.0
```

`gigaam_device: auto` передаёт выбор устройства самой библиотеке GigaAM: при доступной CUDA она может использовать GPU, иначе CPU. Значения `cpu` и `cuda` позволяют зафиксировать устройство явно.

## Установка

Актуальная ветка GigaAM v3 на момент интеграции находится в официальном репозитории `salute-developers/GigaAM`. Она устанавливается отдельно от базовых зависимостей Tutor Assistant, чтобы пользователи faster-whisper не получали обязательную установку PyTorch и связанных пакетов.

Из активного окружения проекта:

```powershell
uv pip install "gigaam @ git+https://github.com/salute-developers/GigaAM.git@559d88d6b72541412743929f633a6ae7c9950b85" "torch>=2.6" "torchaudio>=2.6"
```

Также `ffmpeg` должен быть доступен в `PATH`.

После обновления GigaAM проверяйте совместимость перед изменением закреплённой ревизии: официальный пакет и модельный API развиваются независимо от Tutor Assistant.

## Длинные записи

Обычный API `GigaAM.transcribe()` предназначен для коротких файлов и ограничивает один вызов примерно 25 секундами. Официальный `transcribe_longform()` использует дополнительный VAD-стек на базе `pyannote.audio`, которому нужны дополнительные зависимости и доступ к соответствующим моделям.

Tutor Assistant намеренно не делает этот стек обязательным. Вместо него входное аудио локально конвертируется через `ffmpeg` в mono PCM 16 kHz и делится на последовательные окна по 20 секунд. Каждый фрагмент обрабатывается обычным GigaAM API, а временные смещения восстанавливаются в общую шкалу занятия.

Это даёт простой offline-путь без Hugging Face token и сохраняет существующий контракт транскрипционных артефактов. Цена такого первого варианта — граница фиксированного окна может иногда проходить внутри реплики. Если качество на реальных занятиях потребует улучшения, следующий шаг — локальный VAD или overlap + дедупликация текста.

## Двухканальная транскрибация

Существующая схема не меняется:

- `microphone.wav` распознаётся как преподаватель `[П]`;
- `system.wav` распознаётся как ученик `[У]`;
- сегменты объединяются по времени с учётом `sync_report.json`;
- `teacher_transcript.txt`, `student_transcript.txt`, student signals и общий проверяемый транскрипт создаются тем же pipeline.

Поэтому переход между `faster_whisper` и `gigaam` не меняет дальнейшие этапы ручной проверки, LLM-фильтрации и публикации.

## Артефакты и диагностика

Для GigaAM сырой текст записывается в `00_raw_gigaam.txt`; остальные имена общих артефактов сохраняются. `manifest.json` содержит технические поля `provider`, `model`, информацию об источнике и границах чанков, но не дублирует распознанный текст.

Если GigaAM не установлен, Tutor Assistant завершает конкретное задание транскрибации понятной ошибкой с инструкцией по установке. При этом выбор `faster_whisper` продолжает работать без GigaAM и его зависимостей.
